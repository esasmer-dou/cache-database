# v0.10.0

Turkish version: [../../tr/docs/releases/v0.10.0.md](../../tr/docs/releases/v0.10.0.md)

Release tag: `v0.10.0`

CacheDB `0.10.0` closes the distribution, migration-scaffold, SQL Server write
path, and application cutover-evidence gaps left after `0.9.0`. It is a stable,
additive framework release.

## Main Changes

- Migration scaffold generation now emits a real `@CacheProjectionRecord`, the
  entity-side `@CacheProjectionDefinition` registration hook, and a bounded
  `PartitionedRelationBatchLoader`. The generated files are compiled by an
  integration test with the real CacheDB annotation processors.
- Direct projection columns selected in the planner are mapped automatically.
  Primary key, relation key, and sort key are always included. A computed
  business field remains an explicit application decision rather than an
  unsafe metadata guess.
- Generated entity and projection codecs support UUID, `Instant`, `LocalDate`,
  `LocalTime`, `LocalDateTime`, and the existing scalar types.
- SQL Server same-shape writes execute as batch update, one locked multi-row
  version probe for unresolved rows, and batch insert for rows that are truly
  absent. Stale versions remain no-ops and version conflicts remain failures.
- The live SQL Server evidence lane writes a machine-readable throughput report,
  enforces a minimum operation rate, and repeats after container restart.
- The new `cachedb:certify` Maven goal binds every application evidence file to
  one commit and environment. Incomplete route inventory, parity, Redis memory,
  failover, canary, rollback, or blocker data fails `mvn verify`.
- Public artifacts are available from
  `https://esasmer-dou.github.io/cache-database/maven2` without authentication.
  GitHub Packages remains an optional authenticated mirror.
- [Production Readiness Contract](../../PRODUCTION_GA_CRITERIA.md) is the single
  current maturity and go/no-go source.

## Consumer Setup

```xml
<repositories>
    <repository>
        <id>cachedb-public</id>
        <url>https://esasmer-dou.github.io/cache-database/maven2</url>
    </repository>
</repositories>
<pluginRepositories>
    <pluginRepository>
        <id>cachedb-public</id>
        <url>https://esasmer-dou.github.io/cache-database/maven2</url>
    </pluginRepository>
</pluginRepositories>

<properties>
    <cachedb.version>0.10.0</cachedb.version>
</properties>
```

No GitHub token and no local CacheDB source build are required.

## Production Certificate

Add the `cachedb-maven-plugin:certify` execution described in
[Production Certification](../production-certification.md), then run:

```bash
mvn verify -Pproduction-certification
```

Framework release evidence is not an application cutover certificate. Each
consumer must produce representative route, parity, memory, failover, canary,
and rollback evidence in its own staging topology.

## Compatibility

- Existing `0.9.0` repository declarations remain source compatible.
- Redis-first HOT routes, explicit bounded SQL source routes, asynchronous SQL
  durability, and reflection-free generated implementations are unchanged.
- PostgreSQL and SQL Server use the same application model while retaining
  provider-specific SQL and operational tuning.

## Distribution

- Anonymous Maven2 repository under `com.reactor.cachedb`
- Optional GitHub Packages mirror
- Release bundle: `cache-database-0.10.0-github-release.zip`
- PostgreSQL and SQL Server sample repositories tagged `v0.10.0`

The release bundle contains binary, source, Javadoc, and POM artifacts for all
public modules, the BOM, English and Turkish documentation, checks, and both
runnable sample projects.
