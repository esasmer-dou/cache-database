# v0.11.0

Turkish version: [../../tr/docs/releases/v0.11.0.md](../../tr/docs/releases/v0.11.0.md)

Release tag: `v0.11.0`

CacheDB `0.11.0` is an additive provider and declarative snapshot release. Oracle Database joins
PostgreSQL and SQL Server as a first-class provider without changing the
Redis-first active-route, explicit SQL source-route, projection, warm, or
write-behind model.

## Main Changes

- Added [SnapshotPlan](../snapshot-projections.md): declare source tables, business
  mapping and refresh settings instead of application-specific loaders and warmers.
  CacheDB manages disk spooling, bounded batches, renewable leases and atomic
  catalog publication, preserving the last successful generation on preparation failure.
- Added transaction-consistent snapshot reading for PostgreSQL, SQL Server and Oracle,
  explicit SQL Server isolation prerequisites and connection-pool state restoration.

- Added `cachedb-storage-oracle` and
  `cachedb-spring-boot-starter-oracle`, using Oracle JDBC Thin and `ojdbc17`.
- Added version-guarded, JDBC-batched Oracle `MERGE`, duplicate-race recovery,
  guarded delete, configurable query timeout, transaction isolation, retry
  count, and empty-string policy.
- Added bounded Oracle reads with 900-expression `IN` chunks, row limiting,
  provider-specific value binding, and fail-fast database product detection.
- Added Oracle outbox polling and checkpointing with idempotent multi-pod claim
  behavior. Runtime DDL is disabled by default because Oracle DDL commits the
  current transaction.
- Added Oracle schema discovery, foreign-key route suggestions, dry-run and
  staging warm, side-by-side parity comparison, and Redis memory estimation.
- Added a provider-aware `JdbcSchemaDialect`. Schema create, validation, and
  migration now use provider-specific types, metadata identifier casing, and
  DDL for PostgreSQL, SQL Server, Oracle, and H2 tests.
- Schema bootstrap now fails application startup when configured validation or
  creation reports an issue. It no longer logs a database DDL error and
  continues with an invalid runtime contract.
- Added a complete Java 21 Oracle REST sample with Docker Compose, Oracle DDL,
  seed and warm routes, 59 Postman requests, English/Turkish guides, and live
  Oracle/Redis integration coverage.
- Added an Oracle production-evidence lane covering write/delete semantics,
  stale versions, concurrent upserts, large `IN` sets, outbox checkpoints,
  multi-pod coordination, delayed network behavior, restart recovery, migration
  parity, and a throughput floor.
- Added a self-hosted two-instance Oracle 19c physical Data Guard lane covering
  redo apply, broker validation, planned switchover, forced primary loss,
  multi-address service-name Hikari recovery, the full provider suite after both
  role transitions, and former-primary reinstatement with final no-gap/zero-lag
  readiness checks.
- Made delayed-network evidence derive its upstream host, port, and service from
  the supplied Oracle Easy Connect URL, and made planner warm SQL safe for
  Oracle JDBC `PreparedStatement` execution without a trailing terminator.

## Consumer Setup

```xml
<properties>
    <cachedb.version>0.11.0</cachedb.version>
</properties>

<dependency>
    <groupId>com.reactor.cachedb</groupId>
    <artifactId>cachedb-spring-boot-starter-oracle</artifactId>
</dependency>
```

```yaml
cachedb:
  sql:
    provider: ORACLE
    oracle:
      query-timeout-seconds: 10
      transaction-isolation: READ_COMMITTED
      duplicate-race-retries: 2
      empty-string-policy: REJECT
```

Use application- or Redis-generated identifiers and an explicit numeric
version column. See the [Oracle Provider Guide](../oracle-provider.md) for the
complete contract.

## Supported Oracle Scope

- Oracle Database 19c or newer
- Oracle JDBC Thin with `ojdbc17`
- generated entity repositories, projections, warm/backfill, migration
  discovery and comparison, write-behind, and outbox apply
- scalar JDBC values documented in the provider guide

Generic PL/SQL procedure mapping, Oracle UDT/ARRAY/STRUCT, XMLTYPE, SDO, and LOB
streaming are not claimed by this release. Keep those operations in explicit
application SQL adapters.

## Compatibility

- Existing PostgreSQL and SQL Server application APIs remain source compatible.
- `JdbcStorageProvider.schemaDialect()` has a default implementation, so
  existing third-party provider implementations continue to compile.
- Applications that enabled automatic schema validation or creation and relied
  on ignored failures will now stop at startup. This is an intentional
  correctness gate; fix the schema or disable automatic bootstrap explicitly.
- Oracle empty strings are rejected by default. Select
  `NORMALIZE_TO_NULL` only when the entity contract allows null.

## Distribution

- Anonymous Maven2 repository under `com.reactor.cachedb`
- Optional GitHub Packages mirror
- Release bundle: `cache-database-0.11.0-github-release.zip`
- PostgreSQL, SQL Server, and Oracle sample projects pinned to `0.11.0`

Framework evidence proves the provider contract in the repository's test
topology. Each consumer must still certify route parity, memory, connection
pool behavior, failover, canary, and rollback in its own staging environment.
