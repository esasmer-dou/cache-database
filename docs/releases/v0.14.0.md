# CacheDB 0.14.0

English | [Türkçe](../../tr/docs/releases/v0.14.0.md)

Framework package release. Distribution links and assets are listed on the
[GitHub release](https://github.com/esasmer-dou/cache-database/releases/tag/v0.14.0).
This package is not a certification of an application's production topology.

## Additions

- Typed, state-aware snapshot repositories with plan-cached JSON readers and bounded, single-generation multi-ID reads.
- Optional `cachedb-json` streaming codecs generated by `@CacheJsonRecord`; explicit Jackson-free typed snapshot preparation and reads, without changing legacy mapper configuration.
- Partition-local cursor revisions: unrelated partial refreshes no longer invalidate another partition's pagination.
- Explicit row-local streaming preparation, array-backed JDBC rows, scalar byte estimates and a shared spool JSON generator.
- Namespace-sharded Redis Cluster write/compaction streams with bounded slot-local worker polling and namespace-aware admin backlog; explicit shared scopes remain supported.
- Missing-function self-healing with one retry, deployment-lease coordination and existing version/content-drift checks.
- Clean atomic stream version fields and index invalidation that respects configured or existing query indexes.
- Infrastructure-free entity/snapshot fixtures, atomic batch rollback/idempotency and generated repository constructors accepting CacheSession.
- Lower-allocation fixture queries, non-cryptographic fixture IDs, expiry-before-decode checks and repeatable latency gates with separate cold/warmed results.
- Direct generated JSON token output and explicit fixture comparators/value semantics reduce first-use bootstrap work while preserving legacy writer APIs, policy equality and query ordering.
- Direct default-policy construction, lambda-free versioned/bulk fixture reads and explicit batch-receipt equality avoid unnecessary setup and allocations while retaining defaults, replay semantics and record-compatible hashes.
- Snapshot hot-path cleanup: one column index per JDBC result set, cached fixture payload byte sizes, exact allocation-free UTF-8 sizing for quota checks, regex-free generation validation, and single-pass string validation for generated writers. Canonical empty arrays avoid unnecessary parser/writer setup without weakening JSON limits or changing mapper behavior. Redis pages read the payload format once, rather than once per row; empty-page and error behavior remain unchanged.
- Buffered Redis sequence IDs reuse validated sequence blocks and build Redis keys only on refill. Allocation-size validation, cross-instance uniqueness and failed-refill behavior are unchanged.
- JSON streaming output uses one bounded UTF-8 byte buffer instead of stacked character/charset buffers. Output bytes, split-surrogate handling, stream ownership and failure handling are checked against the previous JDK writer; configured Jackson codecs are unchanged.
- Null entity serialization fails before fixture mutation; a failed encoding cannot become a batch deletion. Release sample exports respect ignore rules and exclude private local files.
- CI retains all first-use and repeated latency samples. Interrupted or failed reruns invalidate previous success summaries.
- The strict 50 ms CI target applies to the Jackson-free generated-codec/snapshot probes, including scenario first use. Original JUnit contracts remain mandatory for correctness; their full-method timings, including caller mapper construction and test-framework setup, are reported separately without being represented as framework-operation latency. This is not a universal runtime SLA.
- Bounded ordinary/batch durability waiting, with explicit test-fixture acknowledgements rather than simulated SQL commits.
- FULL, CLIENT_ONLY and WORKER_ONLY deployment roles; lazy admin services and extracted template/migration endpoint helpers.
- Reentrant locks around blocking ID allocation, outbox initialization and Redis lease operations; Java 17 bytecode compatibility retained.

## Upgrade Notes

SQL write-behind now keeps durable versions/tombstones in `cachedb_write_fence`.
This closes physical-delete resurrection by older in-flight UPSERTs. Provision the
provider migration and perform a drained worker upgrade; old workers bypass this
protection. Business tables are unchanged. See [durable write fences](../durable-write-fences.md)
for transactional, retention, backup and Redis-recovery requirements.

Existing 0.13 public constructors and methods are retained. Recompile consumer
repositories to use the new session constructor and align all artifact versions.
`CacheDatabaseConfig` gains the `runtimeRole` record component. Existing constructor
calls still work, but Java 21 record deconstruction patterns must include the new
component. Review any persisted config representation; public-member compatibility
does not guarantee record-shape or serialized-format compatibility.
The default runtime role remains FULL. Existing complete-catalog mapping behavior
is unchanged; streaming requires an explicit factory call.

Jackson-free JSON is opt-in through `withJsonCodec`. It uses record component
names and strict bounded token parsing, not the application's ObjectMapper
customizations. Existing mapper overloads remain available. See the consumer
guide for supported types, limits and migration checks. This addition does not
guarantee a cold JVM scenario below 50 ms on every target runtime.

Cluster namespaces without a global hash tag use a different key strategy than a
shared-scope deployment. Plan that change as a drained, rewarmed migration; do not
let old and new writers use different key layouts for one entity. Tagged snapshot
application prefixes also change to plan-specific tags and require rewarming.

CLIENT_ONLY requires separate workers with the same registrations. A timeout from
awaitDurable does not retract an accepted write. Multi-ID/page payloads are bounded
to 4 MiB; a single point read retains the ability to return a larger prepared root.

See the [consumer guide](../typed-snapshots-runtime-testing.md) and
[Turkish guide](../../tr/docs/tipli-snapshot-roller-testler.md) for code and operational boundaries.

This release does not add new Oracle RAC/Data Guard or SQL Server Always On
topology certification. Unit fixtures and three-primary Redis tests are not HA
or deployment-specific production acceptance evidence.
