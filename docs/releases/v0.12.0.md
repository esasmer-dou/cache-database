# CacheDB 0.12.0

This release simplifies declarative snapshot preparation without changing its
consistency or publication contract.

## What Changes

- Use generated SOURCE mappings instead of repeating metadata and codec arguments.
- Express equality and nested IN filters with bound values, not SQL concatenation.
- Read scalar records with @CacheSourceRecord and generated constructor decoding.
- Describe relationship direction once with SnapshotRelation.
- Prepare sorted lists, membership lookups and per-root DTO distribution once per refresh.

See the [source reference](../snapshot-source-reference.md) and
[snapshot guide](../snapshot-projections.md) for code and operational limits.
PostgreSQL, SQL Server and Oracle share the new source path.
Provider-specific transaction prerequisites still apply.

## Upgrade

Set the BOM and annotation processor to 0.12.0, then recompile.
Existing explicit SELECT sources and metadata/codec factories remain supported.
No new repository registration, background writer or read-time SQL is introduced.
Compare full payloads before switching mapping code, including duplicates, ordering,
nulls and empty arrays. Use lists for payloads and sets only for membership checks.

Source records are scalar, public, nongeneric top-level records.
The two-column relation helper currently uses String IDs; generic row helpers
support other key types. Business filters and DTO rules are not inferred.
Mixed-case quoted Oracle objects still require explicit SQL sources.

## Distribution

Use the anonymous [CacheDB Maven repository](https://esasmer-dou.github.io/cache-database/maven2/).
GitHub Packages remains available for authenticated consumers.
The GitHub release includes binary, sources and Javadoc JARs, parent/BOM POMs,
and a documentation/artifact ZIP with a SHA-256 checksum.
