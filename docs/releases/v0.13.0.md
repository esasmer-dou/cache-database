# CacheDB 0.13.0

This framework release uses `0.13.0` without a SNAPSHOT or prerelease suffix.
The BOM, provider starters, annotation processor and runnable samples are aligned.
Redis-first reads and explicit SQL routes remain unchanged; the new APIs do not
introduce automatic SQL fallback.

## New APIs

- Source records support OffsetDateTime, LocalTime, BigInteger, Float, Short, Byte and enums through generated decoding.
- Typed Long/UUID relations reuse one source in both directions.
- Snapshot predicates add comparison, range, null and literal-list operations with bound parameters.
- Optional snapshot partition indexes support bounded CursorPage reads without SQL.
- Explicit root scopes enable atomic selected-root refresh; immutable payload reuse reduces unchanged JSON duplication.
- Outbox partitions have independent checkpoints and preserve per-entity order.
- CacheWriteBatch accepts one envelope; each supported provider flushes it in one SQL transaction.
- Pooled SQL sequences share actual allocated values safely with legacy callers.
- Redis client adapters support standalone and Cluster topologies with explicit same-slot atomic scopes.

## Upgrade Checks

Align the BOM, annotation processor and provider starter
at `0.13.0`, then recompile generated bindings. Version numbers alone do not certify
an application's route coverage, memory budget or failover topology.

The CacheDB BOM also aligns Jedis at the framework's required version (5.2.0).
Import it in Spring Boot applications; do not force an older Boot-managed Jedis
version that lacks the pipeline API used by the adapters.

Primitive boolean SQL NULL now fails rather than becoming false. Use Boolean for a
nullable column. `hotEntityLimit=0` disables entity admission; change old unlimited
configurations to `-1`. The omitted default remains 1,000.
Old public constructors/methods remain available; recompile generated source bindings.
Snapshot and queue records have additional components; review record deconstruction,
serialization and equality assumptions in consumer code.
New snapshot storage has index/reference metadata; prepare and certify a separate
namespace before changing an existing deployment's storage contract.

Batch acceptance is not a distributed Redis/SQL commit. Bounded tenant contracts
reject atomic batches rather than bypass quotas. Query index invalidation requires
the configured rebuild/strict-route policy. One atomic Cluster scope stays in one
slot; a single scope is not automatically memory-sharded.

## Distribution

Use the anonymous [CacheDB Maven repository](https://esasmer-dou.github.io/cache-database/maven2/)
with `com.reactor.cachedb:cachedb-bom:0.13.0`. No GitHub token or local framework build
is required. GitHub Packages is an additional channel and requires Maven credentials.
The [GitHub release](https://github.com/esasmer-dou/cache-database/releases/tag/v0.13.0)
includes binary, source and Javadoc JARs, parent/BOM POMs, a bundle and SHA-256 checksums.

## Evidence Boundary

This release does not claim a new physical Oracle Data Guard failover certification.
The licensed Enterprise fixture and self-hosted runner were unavailable for this
version. A missing topology run is not a passed test. RAC, Data Guard, SQL Server
Always On and managed Redis recovery must be verified for the deployment being used.
Package availability is not a full production GA approval or an application cutover certificate.

See [bounded runtime operations](../bounded-runtime-operations.md),
[source reference](../snapshot-source-reference.md) and
[snapshot projections](../snapshot-projections.md) for examples, limits and failure behavior.
