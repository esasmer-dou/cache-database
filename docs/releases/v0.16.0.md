# CacheDB 0.16.0

[Türkçe](../../tr/docs/releases/v0.16.0.md)

## Changes

- Explicit sparse index metadata, single-pass batch column extraction, grouped
  hot-set/tenant touches, and direct generated residual filter/sort access.
- Bounded local single-flight for ID/page/query source loads and configurable
  access-touch debounce. Mutable results remain isolated between callers.
- Generated typed `Binding.Columns` metamodel and snapshot predicate/scope overloads.
- Compile-time validated `@CachePatch`; delta-only queues/SQL UPDATEs across
  PostgreSQL, SQL Server and Oracle, with predecessor/deletion fences.
- Post-durability snapshot dirty-root bridge and optional debounced automatic flush.
- Immediate local durability notifications and adaptive cross-process polling.
- Bounded programmatic and Spring `@CacheTransactional` units of work with genuine
  post-commit acceptance receipts; no fabricated pre-commit versions.
- Bounded trace metadata across streams, recovery and job handlers; standard
  Micrometer binder and Redis/SQL function timers.
- Opt-in segmented, TTL/byte/entry-bounded L1 cache with cross-runtime invalidation,
  disconnect fallback, late-fill protection, and defensive decoding.
- Three Java 21 provider samples demonstrate typed columns, absolute stock PATCH,
  and automatic snapshot wiring. Library bytecode remains Java 17.

## Validation

- Full reactor: 668 tests, no failures or errors. Two environment-gated listener /
  service-name failover tests were not executed.
- PostgreSQL, SQL Server and Oracle samples: 26 tests per provider, all passed.
- Packaged Jackson-free codec: 1260 cold/repeated measurements, all below 50 ms;
  maximum 33.66 ms. This is a codec probe, not a REST or database latency SLA.
- Legacy Jackson contracts passed separately; the maximum first-use measurement
  was 397 ms and is outside the Jackson-free latency gate.
- All three samples compiled against the staged Maven artifacts without a
  framework source checkout. Public API compatibility and Java 17 library /
  Java 21 sample bytecode were checked.

These results use isolated Kubernetes fixtures and do not certify an application's
HA topology or capacity.

## Upgrade and Limits

Read [bounded read/write controls](../hot-path-controls.md) before enabling the
new opt-ins. Align all artifacts and regenerate bindings. Upgrade/drain workers
before enabling PATCH; old workers do not understand the new operation. Preserve
SQL fence metadata and Redis version counters. Default index coverage remains
unchanged until explicitly narrowed. No new business-table columns are required.

L1 is eventual, not linearizable; pub/sub is not a durable event log. Automatic
dirty notifications do not replace periodic reconciliation or external-writer CDC.
Unit-of-work limits remain 100 identities, 4 MiB and 2000 stream fields; Cluster
requires one hash-tag scope. A durability timeout after acceptance is not rollback.
Receipt-returning methods inside a deferred scope fail fast; use explicit `tx`
commands. These changes do not certify application-specific HA, RAC or Data Guard.
