# v0.6.0

Release tag: `v0.6.0`

CacheDB `0.6.0` makes the normal application path more declarative while
preserving explicit limits for memory, source reads, relation fan-out, and
multi-pod work.

## Highlights

- `@CacheDomain(spring = true)` generates the package-level CacheDB domain and Spring configuration.
- `@CacheRelation` can generate a bounded partitioned loader from typed target, parent batch size, per-parent limit, and stable ordering metadata.
- `@CachePartitionedIndex` declares bounded per-parent sorted indexes such as customer plus order date.
- `@CacheProjectionRecord` generates reflection-free projection schema, codec, and optional source-entity mapping.
- `@CacheRoute` adds page size, hot window, cold-read limit, memory budget, projection, and strict-mode rules to generated query routes.
- `WriteReceipt`, `WriteDependency`, optimistic version checks, and durability tracking make Redis acceptance and SQL completion distinct and observable.
- Typed Redis Stream jobs can be claimed by another pod after owner loss; retries, payload/result size, queue capacity, and status TTL remain bounded.
- Spring Boot Actuator health reports Redis, SQL, write-behind backlog, dead-letter, and recovery signals.
- PostgreSQL and MSSQL samples use the same layered, declarative application contract and generated read surfaces.

## Consumer Version

```xml
<properties>
    <cachedb.version>0.6.0</cachedb.version>
</properties>
```

Keep `cachedb-spring-boot-starter`, `cachedb-annotations`, and the
`cachedb-processor` annotation processor on exactly the same version.

## Upgrade Notes

The bundled Redis Function deployment version is now `0.4.0`. Its write
protocol includes expected-version and durable dependency metadata. Keep the
default unless your platform team deliberately manages a matching custom
Function source. During a rolling deployment, do not run different CacheDB
Function sources under the same `libraryVersion` in one shared Redis.

The legacy in-process `Supplier` job submission API remains source-compatible
but is deprecated. It cannot survive pod loss because Java closures cannot be
serialized. Register typed `CacheDistributedJobHandler` implementations for
cluster-wide work.

- PostgreSQL and MSSQL samples passed unit tests and live provider integration tests with Redis 8.
- English/Turkish documentation, provider parity, Postman JSON, and release-package checks passed.
- The GitHub Release bundle contains binary, source, and javadoc jars for every public CacheDB module.

## Production Boundary

Generated APIs remove setup code; they do not remove capacity decisions.
Define bounded hot windows, projection contracts, SQL limits, Redis memory
budgets, retry policies, and rollback evidence for every critical route.
Typed distributed jobs provide at-least-once execution, so handlers must remain
idempotent. Redis acceptance is not the same event as durable SQL completion;
use the durability receipt/health surfaces when the business flow requires that
distinction.
