# CacheDB 0.18.0

Yayın sonrası sağlamlaştırmalar [0.18.1](v0.18.1.md) altında hazırlanır;
yayımlanmış bu tag ve paketler değiştirilmez. Bileşik indeks imzası, causal
Cluster/görev kapsamı, yenileme yaşam döngüsü ve JDBC gruplama tanıları eklenir.
Kaynak dizinleri ve tam ortam skip denetimi de hizalanır. Tenant aggregate
ve facet Lua optimizasyonu **0.19.0'a ertelendi**.

[English](../../../docs/releases/v0.18.0.md)

Bu kaynak sürüm; toplu L1 okumalarını, sınırlı soft-TTL yenilemeyi, minimum entity
sürümü taşıyan causal token'ları, taramalara daha dayanıklı L1 tahliyesini, indeksli
toplamları, deklaratif gruplamayı, bileşik eşitlik indekslerini ve tenant kapsamlı
atomik batch, partition ve projection okumalarını ekler. JDBC işlemlerini bağımsız
anahtarlar arasında gruplamak için açık şema onayı gerekir; ID'lerin farklı olması
tek başına yeterli değildir.

[Ayarlar, örnekler ve sınırlar](../yakin-onbellek-facet-bilesik-indeksler.md).

## Uyumluluk ve Geçiş

- Kütüphane Java 17, derleme ve örnek uygulamalar Java 21 uyumluluğunu korur.
- Mevcut NearCachePolicy ve AggregateResult constructor/metotları korunur.
  Soft TTL varsayılan olarak kapalıdır; mevcut entity veri biçimleri değiştirilmez.
- AggregateResult, decimalAverage alanını ekler. Kesin bir JSON cevap şemanız varsa
  framework record'unu doğrudan sunmak yerine cevap alanlarını ayrı DTO'da belirleyin.
- Eski entity API'lerinin tenant exception tipleri korunur. Yeni facet ve tenant
  batch/partition/projection yollarındaki kapsam ihlalleri IllegalStateException üretir.
- Toplu okuma giriş sırasını ve tekrarları korur; yalnızca Redis'e giden ID'ler tekilleştirilir.
- Binding'leri yeniden üretip processor, BOM, starter, istemci ve worker sürümlerini eşitleyin.
- Yeni bileşik indeksleri kullanmadan önce tüm yazıcıları güncelleyin ve indeksleri yeniden kurun.
- Bileşik indeksler mevcut indeks bakım ve degraded-index recovery sözleşmesini korur.
  Payload ve bütün indeks anahtarları tek bir atomik sorgu snapshot'ı oluşturmaz.
- Tenant sahiplik işaretleri değişmezdir. Causal token, Redis entity sürümünün alt
  sınırını taşır; SQL kalıcılığı veya projection güncelliği kanıtı değildir.
- Kaynak değişikliği; yayın, uygulama kapasitesi veya Always On/RAC/Data Guard
  topolojisinin sertifikalandırıldığı anlamına gelmez.

## Doğrulama

Son çalışma zamanı kaynakları, yalıtılmış bir Kubernetes namespace'inde doğrulandı.
Geliştirici bilgisayarında derleme, test veya çalışma zamanı ölçümü yapılmadı.

| Kontrol | Sonuç |
| --- | --- |
| 23 modülün tam koşusu | 730 test kaydı: 728 çalıştırıldı, topolojiye bağlı 2 test atlandı; hata yok |
| PostgreSQL, SQL Server ve Oracle örnekleri | Her birinde 26 test; hata ve atlama yok; yeni SQL veritabanı/şeması ve temiz Redis test verisi kullanıldı |
| Public API ve generated repository | Mevcut API tabanı korundu; facet/bileşik indeks/soft-TTL derleme kontrolleri geçti |
| Paketlenmiş Jackson'sız codec/snapshot yolu | İlk kullanım ve tekrarları içeren 1.260 ölçümün tamamı 50 ms altında; en yüksek 31,05 ms |
| Legacy uyumluluğu | 60 işlevsel ölçüm geçti; 7 ölçüm 50 ms'ye ulaştı veya aştı, en yüksek 385 ms; ayrı raporlandı |
| Paket içeriği | 19 public modülün binary/source/Javadoc paketleri: 57 JAR; hazırlanan Maven deposunda 21 POM |
| Bağımsız paket tüketimi | Üç örnek de framework kaynak kodu olmadan derlendi; her derleme öncesinde consumer önbelleğindeki CacheDB paketleri kaldırıldı |
| Repo kontrolleri | README bağlantıları/kalitesi, Türkçe metinler, Postman sözleşmeleri, sağlayıcı eşitliği, framework ilkeleri ve benchmark eşikleri geçti |

Katı gecikme ölçümü, senaryonun ilk hazırlık işlerini içerir; JVM başlatma ve derleme
süresini içermez. HTTP, SQL, WAN veya canlı ortam kapasitesi için SLA değildir.
Çalışma pod'u 2 CPU ve 4 GiB ile sınırlandırıldı. Gerçek sağlayıcı test ortamlarıyla
tek Redis ve altı düğümlü Redis Cluster kullanıldı; bu, canlı HA topolojisi sertifikası değildir.

Atlanan testler MssqlListenerFailoverSqlServerTest ve
OracleServiceNameFailoverIntegrationTest idi. Gerektirdikleri gerçek listener/service-name
failover topolojileri yoktu. Uygulamaya özel Always On, RAC veya Data Guard
sertifikası verildiği iddia edilmez.

Yayın öncesi consumer doğrulamasında ayrı hazırlanmış dosya tabanlı Maven deposu
kullanıldı. Dağıtımda, bu testlerden geçen JAR'lar yeniden derlenmeden kullanılır.
