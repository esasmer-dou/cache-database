# v0.9.0

İngilizce sürüm: [../../../docs/releases/v0.9.0.md](../../../docs/releases/v0.9.0.md)

Sürüm etiketi: `v0.9.0`

CacheDB `0.9.0`, doğruluk ve kapasite kararlarını çalışma zamanı sihrinin
arkasına saklamadan deklaratif repository bağlantı kodunu azaltan, eklemeli ve
kararlı bir framework sürümüdür. `0.8.0` sonrasında tamamlanan beşinci on
iterasyonluk mühendislik döngüsünü içerir.

## Temel Değişiklikler

- Annotation processor, query alanıyla aynı adı taşıyan uyumlu metot
  parametresini güvenle çıkarabilir. Tek `WindowRequest`, kullanılmayan tek
  integer limit, ID tipiyle uyumlu lookup parametresi, `CacheWarmTarget` ve warm
  satır limiti de yalnızca rol kesin olduğunda otomatik belirlenir.
- Birden fazla aday varsa tahmin yapılmaz ve derleme durur. Parametre sırası
  veya çalışma zamanı reflection'ı sözleşme olarak kullanılmaz.
- Strict HOT ve sınırlı SOURCE route'lar doğrudan `CursorPage<T>` döndürebilir.
  Generated HOT kodu, sayfayı dönmeden önce coverage'ın güncel ve eksiksiz
  olduğunu doğrulamaya devam eder.
- Cursor devam isteği, ilk istekte doğrulanan sayfa limitini korur.
  `CursorPage.map`, kapalı cursor değerini korur ve tek bir ön boyutlandırılmış
  liste kullanır.
- Her repository için değişmez `RepositoryRouteRef` değerleri içeren generated
  bir `*CacheDbRoutes` companion sınıfı üretilir. Warm planı, coverage denetimi
  ve test probe'u bu tipli referansları doğrudan kabul eder.
- Coverage kapsamı, her query grubunda aynı entity alanına uygulanmış tam bir
  `EQ` koşulu olmak zorundadır.
- Actuator, başlangıç log'u ve Micrometer; HOT route sayısını,
  projection/entity dağılımını, kapsamlı route'ları, bütçeli/bütçesiz route
  sayılarını ve tanımlı bellek bütçelerinin taşma güvenli toplamını gösterir.
  Route adları metric etiketi olarak kullanılmaz.
- Tekil komut kalıcılık yardımcıları, yazmayı kabul etmeden önce pozitif timeout
  ister. Toplu aktarım batching ve backpressure'ı korumak için
  `CacheDurableBatchWriter` kullanmaya devam eder.
- PostgreSQL ve SQL Server sample'ları doğrudan cursor sayfasını, çıkarılan
  parametre rollerini, generated route referanslarını ve değişmez `0.9.0`
  paketini kullanır.

## Korunan Sınırlar

- HOT route yalnızca Redis'i okur. Redis'te bulunmayan veri için gizli SQL
  işlemi başlatılmaz.
- SOURCE route açık, sınırlı, indeksli, keyset sayfalı ve zaman aşımı olan bir
  SQL işlemidir.
- Normal yazma önce Redis tarafından kabul edilir. Çağıran açık ve sınırlı bir
  kalıcılık beklemesi kullanmadıkça SQL kalıcılığı asenkron kalır.
- Repository implementasyonu, codec, route catalog ve Spring adapter'ları
  runtime reflection kullanılmadan derleme sırasında üretilir.
- Büyüyen listelerde projection-first tasarım ve keyset sayfalama korunur.
  Offset sayfalama, generated controller, otomatik SQL fallback ve satır başına
  kalıcılık bekleyen bulk helper eklenmemiştir.

## Kullanılacak Sürüm

```xml
<properties>
    <cachedb.version>0.9.0</cachedb.version>
</properties>
```

Yalnızca bir provider starter seç:

```xml
<dependency>
    <groupId>com.reactor.cachedb</groupId>
    <artifactId>cachedb-spring-boot-starter-postgres</artifactId>
</dependency>
```

veya:

```xml
<dependency>
    <groupId>com.reactor.cachedb</groupId>
    <artifactId>cachedb-spring-boot-starter-mssql</artifactId>
</dependency>
```

## Uyumluluk

`0.8.0` ile karşılaştırıldığında public API farkı yalnızca eklemelerden oluşur.
Mevcut açık annotation alanları ile `HotWindow<T>` ve `SourceWindow<T>`
imzaları geçerlidir. `CursorPage<T>` yine `items` ve `nextCursor` alanlarını
taşır.

Tüketen uygulama yine kendi provider entegrasyon testlerini çalıştırmalıdır.
Daha sıkı coverage kapsam doğrulaması, daha önce güvenli olmayan bir route'u
derleme sırasında görünür hale getirebilir. Bu durum runtime regresyonu değil,
doğruluk kapısıdır.
