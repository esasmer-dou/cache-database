# v0.6.0

Sürüm etiketi: `v0.6.0`

CacheDB `0.6.0`, bellek, kaynak okuma, ilişki genişliği ve çok podlu işler için
açık sınırları korurken uygulama kodunu daha deklaratif hâle getirir.

## Öne Çıkanlar

- `@CacheDomain(spring = true)`, paket düzeyindeki CacheDB domain yüzeyini ve Spring yapılandırmasını üretir.
- `@CacheRelation`; tip güvenli hedef, parent batch boyutu, parent başına limit ve kararlı sıralama bilgisinden sınırlı relation loader üretebilir.
- `@CachePartitionedIndex`, müşteri ve sipariş tarihi gibi parent bazlı sıralı indeksleri tanımlar.
- `@CacheProjectionRecord`, reflection kullanmadan projection şeması, codec ve isteğe bağlı kaynak entity eşlemesi üretir.
- `@CacheRoute`; sayfa boyutu, aktif pencere, SQL'den okunabilecek üst sınır, bellek bütçesi, projection ve strict-mode kurallarını generated query route'una bağlar.
- `WriteReceipt`, `WriteDependency`, iyimser sürüm kontrolü ve kalıcılık takibi; Redis kabulü ile SQL tamamlanmasını birbirinden ayırır ve görünür kılar.
- Tip güvenli Redis Stream işleri, işi başlatan pod kaybolduğunda başka bir pod tarafından devralınabilir; retry, payload/sonuç boyutu, kuyruk kapasitesi ve durum TTL'i sınırlıdır.
- Spring Boot Actuator health; Redis, SQL, write-behind backlog, dead-letter ve recovery sinyallerini raporlar.
- PostgreSQL ve MSSQL örnekleri aynı katmanlı, deklaratif uygulama sözleşmesini ve generated okuma yüzeylerini kullanır.

## Kullanılacak Sürüm

```xml
<properties>
    <cachedb.version>0.6.0</cachedb.version>
</properties>
```

`cachedb-spring-boot-starter`, `cachedb-annotations` ve `cachedb-processor`
annotation processor sürümlerini aynı tut.

## Yükseltme Notları

Paket içindeki Redis Function dağıtım sürümü `0.4.0` olmuştur. Yeni yazma
protokolü, beklenen sürüm ve kalıcı bağımlılık bilgisini taşır. Platform ekibi
aynı sözleşmeye sahip özel bir Function kaynağını bilinçli olarak yönetmiyorsa
varsayılan değeri değiştirme. Rolling deployment sırasında aynı Redis üzerinde
farklı CacheDB Function kaynaklarını aynı `libraryVersion` ile çalıştırma.

Eski, process içi `Supplier` job gönderme API'si kaynak kod uyumluluğu için
korunmuştur ancak deprecated durumdadır. Java closure serileştirilemediği için
pod kaybından sonra başka pod tarafından devralınamaz. Cluster genelindeki
işler için tip güvenli `CacheDistributedJobHandler` implementasyonları kaydet.

## Doğrulama

- 13 modüllü ana reactor, integration testleri, production testleri ve public API uyumluluk kontrolleri yerelde geçti.
- PostgreSQL ve MSSQL örnekleri, Redis 8 ile birim ve canlı provider integration testlerini geçti.
- İngilizce/Türkçe doküman, provider parity, Postman JSON ve release paketi kontrolleri geçti.
- GitHub Release paketi, bütün public CacheDB modüllerinin binary, source ve javadoc jar dosyalarını içerir.

## Production Sınırı

Generated API'ler kurulum kodunu azaltır; kapasite kararlarını ortadan kaldırmaz.
Her kritik route için sınırlı aktif pencere, projection sözleşmesi, SQL limiti,
Redis bellek bütçesi, retry politikası ve geri dönüş kanıtı tanımla. Tip güvenli
dağıtık işler en az bir kez çalıştırma sözleşmesine sahiptir; bu nedenle handler
idempotent olmalıdır. Redis'in komutu kabul etmesi, SQL işleminin kalıcı olarak
tamamlandığı anlamına gelmez. İş akışı bu ayrımı gerektiriyorsa kalıcılık receipt
ve health yüzeylerini kullan.
